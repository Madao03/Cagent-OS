# A股财报 Adapter 规格

## 0. 与 EDGAR 的结构性差异（先看这张表）

**不要把 EDGAR 的心智模型直接搬过来。** 五处根本不同：

| 维度 | 美股 (EDGAR) | A股 | 影响 |
|:--|:--|:--|:--|
| **官方结构化 API** | ✅ data.sec.gov 免费 JSON | ❌ **无公开开放 API** | 🔴 最大差异，决定整体路径 |
| **文件格式** | XBRL + HTML | **PDF 为主** | 解析成本高一个量级 |
| **报告口径** | 单季独立（10-Q） | **全部累计** | 🔴 单季必须差分 |
| **季度覆盖** | Q4 无季报 | 四期齐全，但都是累计 | 差分陷阱遍布全年 |
| **鲜度层** | 8-K Item 2.02 | **业绩预告 + 业绩快报** | A股特有，且更早 |

**一句话**：EDGAR 的难点在"读懂结构化数据"，A股的难点在"根本没有结构化数据 + 口径全是累计"。

## 1. 报告体系

### 1.1 四种定期报告

| 报告 | 覆盖期间 | 法定截止 | 审计 |
|:--|:--|:--|:--:|
| **年报** | 全年累计 | 次年 4/30 | ✅ 强制审计 |
| **一季报** | Q1 | 4/30 | ❌ |
| **半年报** | **H1 累计**（Q1+Q2） | 8/31 | ❌（部分审阅） |
| **三季报** | **前三季累计**（Q1+Q2+Q3） | 10/31 | ❌ |

> ⚠️ 年报与一季报**同为 4/30 截止**，4 月是披露洪峰，两份报告会挤在同一窗口 —— 文档定位逻辑必须能区分。

### 1.2 鲜度层：业绩预告 / 业绩快报（A股特有，≈ LANE 2）

| 类型 | 时点 | 内容 | 精度 |
|:--|:--|:--|:--|
| **业绩预告** | 通常 1 月底前 | 净利润**区间或变动幅度**（如"同比增 50%~70%"） | 粗 |
| **业绩快报** | 通常 2 月 | 营收/净利/总资产等**具体数字**，未审计 | 中 |
| 正式年报 | 4 月底前 | 完整报表，已审计 | 高 |

**触发条件**：净利润为负、同比变动超阈值、扭亏为盈等情形下**强制预告**。

**战略价值**：预告比年报早约 3 个月。这是 A股 版的"及时性 vs 准确性"权衡，和 EDGAR 的 `8-K 早但非结构化 / 10-K 晚但有 XBRL` 完全同构。

> 业绩预告还提供了**免费的"实际 vs 预期"能力** —— 快报/年报落地后与预告区间比对，等价于 EDGAR 那边的 guidance 后验。

## 3. MVP 路径决策

**两条路，MVP 建议走 A：**

| | A. akshare 主力 + 巨潮溯源 | B. 自解析巨潮 PDF |
|:--|:--|:--|
| 成本 | 低（接口现成） | 高（PDF 解析 ≈ 重做一遍 LANE 2） |
| 数据质量 | 二手，需标注 | 一手权威 |
| 可追溯 | 靠巨潮公告索引补 | 天然可追溯 |
| **建议** | ✅ **MVP** | P2 再说 |

**A 路径的诚实做法**：
1. 数字走 akshare，**全部标注 `source=akshare, tier=secondary`**
2. 同时查巨潮公告索引，**附上原始公告 URL**（可追溯，即使不解析）
3. 用 §5 的**三表勾稽**替代交叉验证（单源场景下的质量保障）

## 4. 累计口径差分（🔴 最大陷阱）

### 4.1 规则

**A股 不存在"单季报表"。** 单季数据必须差分：

```
Q1 单季 = 一季报                      （唯一不用差分的）
Q2 单季 = 半年报   − 一季报
Q3 单季 = 三季报   − 半年报
Q4 单季 = 年报     − 三季报
```

**这和 FMP 给小鹏推算 Q4 是完全同构的问题** —— 任何聚合商给你的"A股 Q3 单季"，都是它自己算的推算值。

### 4.2 强制处理

| # | 规则 |
|:--:|:--|
| ① | 落库时**同时保留累计值和差分值**，字段分开：`revenue_cumulative` / `revenue_quarterly` |
| ② | 差分值必须标 `derived=true` + `derived_from=[两份报告的公告ID]` |
| ③ | **审计状态跟着来源走**：Q4 差分值 = 年报(审计) − 三季报(未审计)，**结果不是"已审计"** |
| ④ | 差分出现负值 → **flag 不 reject**（可能是真实的减值/退货/追溯调整） |
| ⑤ | 资产负债表科目**是时点值，禁止差分**（总资产/净资产不能相减） |

**⑤ 极易写错**：利润表和现金流量表是期间累计（可差分），资产负债表是时点快照（不可差分）。同一套差分逻辑套到三张表上，资产负债表数据会被彻底毁掉。

## 5. 三表勾稽校验（单源场景的质量保障）

A股 只有一个可用数据源时，**交叉验证做不了，但内部一致性可以做**。这套校验不需要第二个数据源：

```
① 会计恒等式    资产 = 负债 + 所有者权益                    容差 <0.1%
② 现金流勾稽    期末现金 = 期初现金 + 现金流量净额           容差 <0.5%
③ 利润表勾稽    营收 − 成本费用 − 税 ≈ 净利润                容差 <1%
④ 净利润一致    利润表净利润 = 现金流量表间接法起点          应完全一致
⑤ 权益变动      未分配利润变动 ≈ 净利润 − 分红              容差 <2%
⑥ 累计单调      前三季累计 ≥ 半年累计 ≥ 一季（营收类）      违反即 flag
```

**这比"多源投票"更强** —— 它检验的是数据的内在结构，而不是两个可能同源的数字是否相等。

> 可接入现有 `fin-skill-dq-guard`。

## 6. 代码体系与板块分支

```
沪市主板    600/601/603/605xxx   → .SH
科创板      688xxx               → .SH
深市主板    000/001/002/003xxx   → .SZ
创业板      300xxx               → .SZ
北交所      8xxxxx / 4xxxxx      → .BJ
```

**必须处理的特殊状态**（影响数据可比性）：
- **ST / \*ST**：风险警示，财务异常信号本身有投研价值 → 落库为字段
- **退市整理期**：数据不连续
- **停牌**：行情缺失，非数据错误

## 7. 两个静默错误高发区

### 7.1 追溯调整/重述（≈ LANE 2 的重述检测）

A股 会计政策变更、会计差错更正会导致**上年同期数被追溯重述**。
表现：同一期间的数字，在不同报告里不一样。

处理（照搬 LANE 2）：
```
去重 key = (代码, 期间起止, 科目)
同 key 值不一致 → restated=true，保留双值 + 各自公告ID，不静默覆盖
优先级：披露时间更晚的胜出
```

### 7.2 送转股导致每股指标不可比

送股/转增/配股会改变股本，**EPS、每股净资产在时间序列上不可直接比较**。

处理：**每股类指标必须与股本变动事件绑定**，跨除权日的同比计算需复权。
这是 A股 特有的、不做就会静默出错的地方（美股拆股相对少）。

## 9. 测试与反例基线

**Tier 1（fixture）**
- 存 akshare 返回快照 + 巨潮公告索引快照
- 覆盖：四种报告、业绩预告、业绩快报、ST股、送转股、追溯重述

**反例基线**
```
❌ 资产负债表科目不得被差分（总资产/净资产）
❌ 差分值不得标注为 audited=true
❌ 半年报数字不得被当作 Q2 单季
❌ 三季报数字不得被当作 Q3 单季
❌ akshare 数据不得标注为 tier=primary
❌ 跨除权日的 EPS 同比不得未复权直接比较
```

前四条对应最容易犯的口径错误，第五条对应源分层，第六条是 A股 特有。

**内部一致性测试**：任取一家公司一期报告 → 跑 §5 六条勾稽 → 全部通过。
