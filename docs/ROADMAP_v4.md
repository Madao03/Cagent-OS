# CagentOS 开发路线图 v4

> 更新日期: 2026-08-07
> 状态: Beta online at cagentos.com (2026-08-07)
> 基于: v3 路线图 + Beta 上线后的优先级重评估

---

## 背景

v3 路线图停留在 2026-07-13（阶段 4a/4b）。实际上项目已远超该进度：
- Web UI (HTML + vanilla JS) 已上线运营 (2026-08-07)
- SEC EDGAR LANE 1/2 ✅
- Crypto Data Adapters (4 源 × 7 capability) ✅
- Provenance System (P0-c + P1 派生链) ✅
- Pre-launch Baseline (n=24, 0% failed, 21.6% hallucination) ✅
- 用户注册/认证/JWT ✅
- 安全加固（主聊天端点强制认证 + 邀请码端点锁定）✅

本版路线图基于"已上线运营"的现实重新排列优先级。

---

## 核心原则

1. **反馈驱动优先级** — Beta 刚上线，优先级由真实用户反馈决定，不预先排死
2. **8 不是独立阶段** — trace/自优化/记忆拆三层（L1/L2/L3），L1 融进观点库一起做
3. **React 渐进迁移** — 观点库（4）作为切 React 的第一个页面，老页面暂不动
4. **multiagent 等需求驱动** — 后端 Supervisor 已 ready，适配工作等用户反馈触发

---

## 近期 — 铺反馈闭环

> 目标：打通反馈渠道，为后续所有决策提供数据支撑

| 序号 | 项目 | 技术栈 | 核心目标 | 依赖 | 预估 |
|:---|:---|:---|:---|:---|:---|
| **1** | 路线图 page | vanilla | 展示开发进展给用户看，管理路线图 | 无 | 1 天 |
| **2** | 反馈中心 page | vanilla | 接收用户反馈（文字 + 截图），最小反馈闭环 | 无 | 1-2 天 |

**里程碑：反馈渠道打通 → 放心扩到 15 人内测**

---

## 中期 — 差异化价值 + 数据闭环

> 目标：让用户在 CagentOS 上留痕，采集自优化信号

| 序号 | 项目 | 技术栈 | 核心目标 | 依赖 | 预估 |
|:---|:---|:---|:---|:---|:---|
| **4** | 观点库 | **React（基建切入）** | 选中回答 → 引用/存入/点赞点踩/报错 | 无 | 5-7 天 |
| **8-L1** | 埋点层 | React + 后端 | 采集反馈信号（点赞/点踩/追问率/停留时长） | 与 4 同步设计 | 含在 4 内 |
| **7** | multiagent 前端接入 | React | 后端 Supervisor 适配到 Web 请求流，前端展示 | 4 完成（共用 React 基建） | 3-5 天 |

**里程碑：用户能留痕 + agent 能采集反馈信号**

---

## 中后期 — 质量深化

> 目标：基于数据优化 agent 理解力与个性化

| 序号 | 项目 | 核心目标 | 依赖 | 预估 |
|:---|:---|:---|:---|:---|
| **8-L2** | 画像/记忆优化 | 基于埋点数据构建用户画像，注入 prompt | L1 运转 2-4 周 + 有数据 | 3-5 天 |
| **3** | 微信公众号抓取 | Playwright 落地 | 无（可穿插） | 2-3 天 |
| **4.5** | Skill 优化 | 投研框架沉淀为 skill（含产业链 graph/冲积图评估） | 8-L2 有用户偏好数据 | 待评估 |

## 远期 — 功能扩展 + 打磨

| 序号 | 项目 | 核心目标 | 依赖 | 说明 |
|:---|:---|:---|:---|:---|
| **5** | 嵌入式 skill + 用户自带 API key | 个性化注入框架 + 自带模型 | 安全存储 + 模型路由改造 | 需单独规划 |
| **8-L3** | 自优化层 | prompt 自适应 → SFT/DPO | L2 稳定 + 数据量足够 | 远期 |

| **9** | 信息流工具 | 真正去噪，用户只关注的信息 | 与 10 有重合 | 需单独设计 |
| **10** | watchlist 工具 | 日报 page + 定制化看板 | 9 设计收敛 | 需单独设计 |
| **11** | 前端统一 React | 老页面迁移 + CSS tokens 全局统一（消除多页面重复定义） | 各功能稳定后 | 渐进 |

## 关键决策记录

| 决策 | 理由 |
|:---|:---|
| 观点库（4）是切 React 的第一个页面 | 新功能、交互密集、值得基建投入；老页面保留 vanilla |
| 8 的 L1 和 4 一起设计 | 观点库的点赞点踩/报错就是自优化的反馈信号源 |
| 4.5/9/10 由反馈驱动优先级 | Beta 刚上线，不预先排死 |
| 多 Agent 前端接入等需求触发 | 后端 Supervisor 代码已 ready，适配工作量等用户反馈 |
