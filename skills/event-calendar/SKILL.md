# Event Calendar Engine — 事件日历引擎

> 不分析市场现状，只回答一个问题：**"接下来 N 天有哪些事值得我把注意力放上去？"**

## 使用方式

| 方式 | 触发词 | 备注 |
|:----|:------|:----|
| On-demand | "帮我看看下周有什么大事" | 即时运行 |
| Cron（推荐） | 每周日凌晨自动跑 | 推送到每日简报 |

## 默认参数

- **时间跨度**: 未来 14 天（可用户指定）
- **最大事件数**: ≤ 10 个
- **复盘触发**: 事件结束后 +24h（仅对"有明确数值输出"的事件）

---

## 执行步骤

### Step 0: 加载 data-source-handbook

获取完整数据源注册表，后续所有数据获取优先使用已注册的源。

### Step 1: 确定时间窗口

默认从当前日期起未来 14 天。用户可指定："下周" / "本月" / "6月5号到6月15号"。

### Step 2: 数据收集 — 四路并行

#### 2a: 金十 MCP list_calendar 获取经济日历（主力结构化源）

- ⭐4-5星事件 → 🔴 高优先级
- ⭐3星事件 → 🟡 中优先级
- star=1-2或无星 → 合并到上下文摘要，不进主列表
- 金十数据优先于 web_search 的同类事件

#### 2b: Web search 获取事件定性上下文（补充源）

仅当金十 calendar 已识别出该事件或搜索结果明显超出金十覆盖范围（加密专属事件、地缘政治等）时使用：

```
1. "FOMC [month] [year] market expectations"
2. "major earnings calendar [month] [year]"
3. "[key event] analysis impact"
4. "geopolitical deadlines [month] [year]"
5. "crypto events [month] [year] unlocks halving"
```

#### 2c: 结构化数据源辅助确认

| 事件类型 | 确认方式 |
|:--------|:--------|
| FOMC 日期 | 金十 calendar + CME FedWatch 交叉确认 |
| CPI/PCE/非农日期 | 金十 calendar + FRED series 发布日期查询 |
| 市场数值事后验证 | Yahoo Finance 验证事后价格 |

#### 2d: 白名单固定事件

预置可预测的固定事件作为兜底（加密峰会/减半/ETF裁决截止日/代币解锁日等）。

### Step 3: 交叉验证

每一条待采用的事件记录血统：

```
事件: [事件名称]
日期: [日期]
来源: [哪个搜索/哪个结构化源]
确认方式: [2 个独立来源一致 → 采用 / 不一致 → 标记待定]
数值交叉验证: [含数值时 API-to-API 对比，偏差 > 5% 取均值并标注]
```

### Step 4: 排序 & 筛选

| 级别 | 事件类型 | 处理 |
|:---:|:--------|:----|
| 🔴 高 | FOMC / 超级财报 / CPI / 非农 / 地缘危机里程碑 | 必留，详细推理 |
| 🟡 中 | 普通财报 / PMI/ISM / 通膨数据 / OPEC / 峰会 | 保留但简洁 |
| 🟢 低 | 常规讲话 / 常规数据发布 / 例行会议 | 超 10 个时剪掉 |

### Step 5: 逐事件推理 & 格式化输出

每条事件按 A+B+C 格式：

```
⚡ [日期] — [事件名称]
影响: [资产/板块/叙事]
逻辑: [因果链 1-2 句]
数据:
  ├─ [关键数据点 A]: [值] → 来源
  └─ [关键数据点 B]: [值] → 来源
方向: [偏多 / 偏空 / 中性 / 事件敏感型]
查证: [用户可自行验证的方式]
```

**推理原则：**
- 只说客观因果链，不押方向
- 方向判断必须附带"基于 X 数据"的说明
- 所有数据点标注精确来源，确保用户 30 秒内可查证
- 禁止使用 LLM 记忆中出现的数字——所有数据必须是刚获取的

## 复盘流程

### 冷复盘（自动触发 +24h）

对"有明确数值输出"的事件（FOMC / CPI / Earnings 等）：

1. 读取 event-log → 找到该事件的原始推理
2. web_search 事件实际结果
3. 对比原始推理 vs 实际结果
4. 判断偏差类型 → 写入 event-log

### 热复盘（用户主动反馈）

用户说"这个推理/数据不对"→ 立刻执行：
1. 确认用户指出的具体偏差点
2. 回溯当时使用的数据来源和数值
3. 判断偏差类型
4. 当场修正并追加记录

### 偏差判断

```
[数据不准] → 使用的原始数据有误
  应对: 改善数据源 / 增加验证步骤

[推理偏差] → 数据正确，但因果链错了
  应对: 修正推理逻辑 / 增加考量维度

[方向误判] → 数据对、逻辑对，但市场反应方向相反
  应对: 下次同类事件增加"市场情绪"考量维度
```

## 注意事项 / 局限性

1. **金十 MCP 依赖** — MCP 服务故障时自动降级到 web_search
2. **金十覆盖范围** — 主要覆盖传统金融事件，加密专属事件（代币解锁/ETF裁决/链上治理）由 web_search 和白名单覆盖
3. Web search 不保证 100% 覆盖 → 建议用户自行补充
4. 自动复盘仅对"有明确数值输出"的事件执行
5. 预测方向是"基于现有数据的最优推断"，不是投资建议
6. 选中前 10 个足以覆盖 80% 的注意力价值
