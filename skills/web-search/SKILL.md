# 网络搜索策略（Web Search）

## 核心纪律：信息检索四步法

**任何需要外部信息的问题，按以下顺序执行，不可跳步：**

| 步骤 | 动作 | 工具 | 什么时候跳过 |
|:--:|:-----|:-----|:-----|
| **0** | 确认知识库状态 | `financial.rag.status` | 永远不跳过——先知道有什么 |
| **1** | 搜本地知识库 | `financial.rag.search` | 知识库不可用或 chunk=0 |
| **2** | 网络搜索 | `financial.websearch` / `panews.search` | 步骤 1 有高质量命中且未过时 |
| **3** | 全文抓取 | `web.fetch` / `web.fetch_weixin` | 搜索结果摘要已足够回答 |

## 什么时候不需要搜索

以下场景**跳过搜索**，直接用分析能力回答：
- 纯分析框架问题（"怎么估值"、"PE 和 PB 的区别"）
- 用户明确引用已有内容（"上次说的那个..."）
- 纯逻辑推理（"如果降息 25bp，对 BTC 有什么影响"——需要的是因果链，不是新数据）

## 步骤 0: 确认知识库状态

```
1. 调 financial.rag.status → 获取 chunk_count, embedding_model, available
2. 如果 available=false → 直接进入步骤 2（网络搜索）
3. 如果 chunk_count=0 → 同上
4. 如果知识库正常 → 进入步骤 1
```

## 步骤 1: 搜索本地知识库

- **工具**: `financial.rag.search(query="...", top_k=5, use_rerank=true)`
- **返回**: 匹配的文本片段 + 来源文件 + 相关性分数
- **判断标准**:
  - 相关性 ≥ 0.7 + 发布 < 7 天 → 可用，标注日期和来源
  - 相关性 ≥ 0.7 + 发布 ≥ 7 天 → 可用但标注"⚠️ 可能过时"
  - 相关性 < 0.5 或无结果 → 进入步骤 2

## 步骤 2: 网络搜索

### 渠道选择（按问题类型匹配，不要只用 websearch）

| 问题类型 | 首选工具 | 次选 | 说明 |
|:-----|:-----|:-----|:-----|
| 加密新闻/快讯/hot topics | `panews.search` | `panews.briefing` | 中文加密资讯专用，编辑精选 |
| 加密趋势/市场情绪 | `panews.briefing` + `panews.trending` | `panews.search` | 今日必读 + 24h热度榜 |
| 加密事件/会议 | `panews.events` | `financial.websearch` | 活动日历 |
| Polymarket 预测市场 | `panews.polymarket` | — | 智能资金仓位 |
| 美股/A股/宏观/通用 | `financial.websearch` | — | DDG 多 provider |
| 微信公众号文章 | `web.fetch_weixin` | `financial.websearch` | 需要 WSL Playwright |

### 搜索词构造

**不要直接把用户问题当搜索词。** 拆解 → 提取实体 → 构造 2 组搜索词：

```
1. 从问题中提取核心实体（标的/指标/事件/时间）
2. 构造中文搜索词：核心实体 + 限定词 + 时间范围
3. 构造英文搜索词：英文标的/术语 + 限定词
4. 两组各搜一次，最多 2 轮
```

**示例**:
- 用户问："NVDA 最新财报毛利率怎么样"
- 中文: `NVDA 2026 Q2 毛利率 财报`
- 英文: `NVIDIA gross margin Q2 FY2027 earnings`
- 加密问："最近 BTC ETF 资金流向"
- 中文: `BTC ETF 资金流入 2026年7月`
- 英文: `Bitcoin ETF flows July 2026`
- 同时用 `panews.search(query="BTC ETF 资金流入")`

### 网络搜索结果判断

```
搜到 5+ 条 → 选前 3 条最相关的抓全文（步骤 3）
搜到 1-4 条 → 全部评估，可信度高的抓全文
搜到 0 条   → 换关键词重试 1 次 → 仍 0 条 → 诚实告诉用户
```

## 步骤 3: 全文抓取

- 步骤 2 搜到的 URL → `web.fetch(url)` 或 `web.fetch_weixin(url)`
- 抓取失败的情况:
  - **反爬保护** → 告诉用户 URL + "该网站有反爬保护，建议手动访问"
  - **付费墙** → 告诉用户 URL + "该内容需要订阅，可从摘要获取部分信息"
  - **超时（>30s）** → 放弃该 URL，用其他来源
- **不要对所有 URL 抓取**——选最相关的 2-3 个即可，避免浪费时间

## 时效性判断（对接 BASE_AGENT_PROMPT 数据分级）

| 数据等级 | 内容 | 过时标准 | 过时后怎么办 |
|:--:|:-----|:-----|:-----|
| **L1 快变量** | 价格、利率、汇率 | > 1 天 | 不用搜索——直接用 `financial.quote.query` / `financial.fred` |
| **L2 中变量** | 财报、非农、CPI、政策决议 | > 1 个发布周期 | 搜索最新发布 + 标注"上次发布: YYYY-MM-DD" |
| **L3 慢变量** | 产业结构、人口趋势、技术路线 | > 6 个月 | 搜索最新研报 + 对比历史观点的变化 |

## 多源交叉验证

- **重要数字**（GDP、通胀、公司营收、ETF 规模）：至少 2 个独立来源确认
- **单一来源的独家数据**：标注"⚠️ 单一来源，待核实"
- **两个来源差异 > 5%**：标注矛盾 + 列出双方数字 + 不做偏向性取舍
- **搜索结论 vs 知识库结论矛盾**：标注冲突 + 注明各自时间戳 → 提示用户注意

## 搜索结果可信度标注

每个引用的外部信息必须标注：**来源名称 + 发布日期 + 可信度**

| 可信度 | 来源类型 | 示例 |
|:--:|:-----|:-----|
| 🟢 高 | 交易所公告、监管文件（SEC/CFTC/PBOC）、.gov、知名机构研报 | FOMC Statement, 13F filing, Grayscale 月报 |
| 🟡 中 | 主流财经媒体、行业垂直媒体、PANews | Bloomberg, 金十, PANews, 财新 |
| 🔴 低 | 个人博客、Twitter/社交媒体、无署名来源 | Medium, X posts, 论坛帖子 |

## 搜索失败处理矩阵

| 失败情况 | 处理 |
|:---------|:-----|
| RAG status 返回 unavailable | 跳过步骤 1，直接进入网络搜索 |
| RAG search 返回 0 条 | 进入网络搜索 |
| PANews 返回 0 条 | 换 `financial.websearch`，用英文关键词 |
| websearch 返回 0 条 | 换关键词重试 1 次，仍 0 条 → 诚实告诉用户 |
| web.fetch 返回反爬 | 告诉用户"该网站有反爬保护，无法自动抓取，建议手动访问：URL" |
| web.fetch 返回付费墙 | 告诉用户"该内容需要订阅，建议手动访问：URL" |
| 知识库 + 网络都搜不到 | 诚实说"未找到相关信息"，不要编造 |
| 搜到了但全是低可信度来源 | 如实告诉用户来源质量，不隐藏 |

## 禁止行为

- ❌ **不搜索就回答**（对于数据/新闻/实时信息类问题）
- ❌ **跳过步骤 0-1 直接搜外网**（知识库是 L1，外网是 L2）
- ❌ **编造搜索结果**（搜不到就说搜不到）
- ❌ **用过时数据不标注时效性**
- ❌ **只搜一个关键词就放弃**（至少换 2 种关键词 + 中英文各尝试）
- ❌ **把搜索结果当定论**（所有搜索结果都需要可信度标注）
- ❌ **对所有 URL 逐一抓取**（选最相关的 2-3 个即可）
- ❌ **加密问题不调 PANews**（加密新闻的首选渠道）
